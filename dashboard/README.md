# Spider-Sense — Dashboard

Next.js dashboard that visualizes the privacy risk score, sensitivity matrix, and plain-English explanation for a scan.

## Setup

```bash
cd dashboard
npm install
npm run dev
```

By default this runs on `http://localhost:3000`.

## Configuration

Point the dashboard at your backend API — typically via an environment variable, e.g.:

```bash
# .env.local
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Update this to your deployed backend URL before the final demo.

## What it renders

For a given scan, the dashboard consumes the merged response from `POST /api/scan` (see [`docs/api-contract.md`](../docs/api-contract.md)) and displays:

- **Privacy score** and overall `risk_level` (low / medium / critical)
- **Sensitivity matrix** — each detected field with its tier (low/medium/high/critical), whether it's `reasonable` for the page, and the rule engine's `notes`
- **Explanation** — the `explanation.summary`, `explanation.evidence[]`, and `explanation.recommendation` fields, shown in plain language. These are generated by rule-based templating in the backend, not a live AI call, so responses should be fast and consistent.
- **Loading / error states** — while a scan is in progress, and if the backend is unavailable

## Demo Scan fallback

If the extension isn't available (e.g. during judging), the dashboard should support triggering a scan manually with one of the sample payloads in [`data/`](../data) — this is the fallback path described in [`docs/demo-flow.md`](../docs/demo-flow.md).
